Generated by `npm run demo:shots` (`e2e/demoShots.spec.ts`) into `docs/demo/screenshots/`. All eight are pre-baked — zero live AI calls — except `diff-view.png`, which is opt-in (`DEMO_SHOTS_WITH_LIVE=1`) since it's the one shot that genuinely requires a real AI response.

|---|---|:-:|:-:|:-:|

## Picking a README hero

Use `dashboard.png` — it's the one shot that communicates the whole product ("AI-assisted CMS with health scoring") without needing any surrounding caption. The restructured README puts it immediately under the one-line pitch.

## LinkedIn post structure (suggested)

A 2-3 image post reads better than a wall of text:
1. `dashboard.png` — "what is this"
2. `diff-view.png` (if captured) or `page-editor.png` — "what does using it look like"
3. `cost-dashboard.png` — the production-minded detail (spend caps, fallback logging) that signals this isn't just a toy demo

Caption should point at the demo video (once recorded, per `script.md`) and the repo link, not try to explain the whole feature set in text — the images and the 2.5-minute video are the real pitch.
